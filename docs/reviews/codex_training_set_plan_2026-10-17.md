# Codex review: pragmatic plan for the 9-D emulator training set (2026-10-17)

Codex CLI, effort medium, read-only. Adopted: calibration tranche first, float64 sprays + per-star numerator/denominator, combined-corner preflight, corotation root per variant host, transitive source + input-file hashes. Not adopted: per-bin per-star contributions (recomputable from the stored sprays).


**The noise premise does not match the proposed target:** the existing study explicitly scores **pooled** debris; its scatter does not establish fixed-bin noise or bias ([neff_study.py:44](bin/streams/neff_study.py:44)). Equal chi weights also retain density dependence through the foreground/background denominator ([score.py:327](src/ocen_dm/streams/score.py:327)).

Changes ranked by importance:

1. **Launch a calibration tranche, then gate the remaining jobs.** Keep 256k provisionally; compare 128k/256k at equal cost using the actual fixed-bin score. Give a few representative points 8–16 independent seeds, including sparse/extreme cases, rather than treating four seeds at eight points as validated noise calibration. Save per-star numerator **and** denominator in float64; estimate total-score noise across seeds, preserving cross-star covariance. `n_eff` measures joint foreground concentration only ([score.py:325](src/ocen_dm/streams/score.py:325)). The existing convergence test concerns pooled scoring and only two sample sizes ([test_score_conditional.py:113](tests/test_score_conditional.py:113)). **Neither resolution is established as sufficient.**

2. **Preflight the combined physical extremes.** `vc_target` and `halo_q` compose algebraically, with rejection of nonpositive halo normalization ([mw_variants.py:38](src/ocen_dm/streams/mw_variants.py:38)); the target-speed test exercises only default flattening ([test_mw_variants.py:27](tests/test_mw_variants.py:27)). Check combined corners for achieved speed, finite forces and nonnegative total density. Especially check large amplitude/size: the host adds a scaled **difference** of baryonic potentials, without a density-positivity check ([restricted.py:94](src/ocen_dm/streams/restricted.py:94)). Corotation alone does not establish physical admissibility.

3. **Keep the S mapping, but implement corotation independently of the old helper.** Solve \(v_c(R)/R=\Omega_b\) using each point’s variant host; require a bracketed root and upper limit ≥0.8. The existing helper uses the original host and interpolation, so cannot implement your proposed constraint ([refine_bar_profiles.py:57](bin/streams/refine_bar_profiles.py:57)). Your mapping samples S uniformly *conditional on the other parameters*; it does not sample uniformly over the constrained physical volume. That is acceptable for emulator design; specify inference priors separately.

4. **Strengthen preservation before launch.** Save every returned particle, including negative/out-of-range chi, plus release index and `age_cut_myr`. Preserve chi/age in float64: hard bin/age cuts make float32 rounding potentially consequential ([score.py:282](src/ocen_dm/streams/score.py:282), [score.py:292](src/ocen_dm/streams/score.py:292)). Add per-bin counts and joint/u contributions; current diagnostics expose only their aggregate ([score.py:330](src/ocen_dm/streams/score.py:330)). Tracks can wait. `xv` is optional for present-coordinate rescoring; the proposed observables already supply the wrapper’s inputs ([grid4_common.py:90](bin/streams/grid4_common.py:90)).

5. **Separate spray identity from score identity.** A scoring change should create new score records without invalidating valid sprays. Hash external potential files, mass profile, frame/projection inputs, ordered data and transitive source dependencies—not merely the five named sources. Those inputs enter through external files and imported transformations ([restricted.py:97](src/ocen_dm/streams/restricted.py:97), [grid4_common.py:17](bin/streams/grid4_common.py:17), [frames.py:21](src/ocen_dm/streams/frames.py:21)). Use unique temporary files per worker and verify artifact hashes before skipping.

**Safe later:** GP/kernel choice, final chi cutoff, correction implementation and additional design points—provided the particles and calibration quantities above survive. Correction *validation* must precede interpreting emulator likelihood differences. Fixed-bin densities themselves divide by random bin occupancy, so the proposed delta correction is not automatically complete ([score.py:323](src/ocen_dm/streams/score.py:323)).
