**The current optimization violates the hard requirement as written.** `make_spray` now returns only particles younger than 700 Myr, so callers that inspect the full trailing stream receive fewer particles than before; the cutoff happens in `spray_unwrapped` before its result is returned to `make_spray` [grid4_common.py:53–55](./bin/streams/grid4_common.py#L53) [spray.py:121–129](./src/ocen_dm/streams/spray.py#L121). For the likelihood alone, this pruning is equivalent when `age_max=700`: the scorer selects `chi > 0` and `age < age_max` [score.py:250–253](./src/ocen_dm/streams/score.py#L250). But that does not preserve the complete returned stream. Treat the age cutoff as **C** under the PI’s strict requirement; it is **A** only if the requirement is explicitly limited to score-relevant particles.

### Ranked speedups

1. **Keep the pruning only if the PI accepts score-equivalent output.** Initial conditions are generated before the mask is applied, including spin velocities, and the release epochs and progenitor orbit are computed before pruning [spray.py:111–120](./src/ocen_dm/streams/spray.py#L111) [spray.py:121–129](./src/ocen_dm/streams/spray.py#L121). The regression test checks exact equality for the retained particles against two stored runs, and checks a separate full-versus-subset run [test_spray_subset.py:17–46](./tests/test_spray_subset.py#L17). **A for the retained subset**, subject to the coverage limits below; **C for preserving the full returned stream**.

   The scoring guard is not reliable: it hardcodes 700 and infers truncation from the largest returned age [grid4_common.py:58–62](./bin/streams/grid4_common.py#L58). A spray cut at 500 Myr can therefore be scored with `age_max=600` without an error; a shorter release window can also make an untruncated spray appear “cut.” Store the cutoff explicitly with the model and validate `age_max` against that metadata, or require the caller to pass the cutoff. Add tests for cutoffs below and above 700 and for short windows.

2. **Reuse deterministic setup across seeds.** Within one model, `host_potential`, the backward and forward centre orbits, release-time interpolation, and `rj_vj_R` are recomputed before particles are drawn and integrated [grid4_common.py:49–54](./bin/streams/grid4_common.py#L49) [spray.py:111–120](./src/ocen_dm/streams/spray.py#L111) [spray.py:22–39](./src/ocen_dm/streams/spray.py#L22). Cache or pass these arrays and the host potential across seeds for the same parameters. **A**, if the cache key includes all inputs that affect them and cached arrays are reused unchanged. Do not reuse across changed host, distance, frame, release settings, or mass profile.

3. **Reduce trajectory samples only as a measured approximation.** Each particle currently has 240 trajectory samples; `chi` is integrated with a trapezoid over those samples, while `psi` is computed in the same per-particle loop [spray.py:96–108](./src/ocen_dm/streams/spray.py#L96) [spray.py:136–143](./src/ocen_dm/streams/spray.py#L136). Fewer samples change the numerical quadrature for `chi`, so classify this **B**, not A. Benchmark `ntraj` values such as 120, 60, and 30 against 240. A reasonable proposed acceptance test is, across fixed representative models and seeds, maximum per-star log-likelihood change below 0.1 and total log-likelihood change below 1; also report maximum changes in stream observables relative to the measurement errors. The code does not establish how much runtime is trajectory output versus force integration, so measure both elapsed time and memory before expecting a large gain.

   Skipping `psi` is a small **A** opportunity for the `make_spray` path: it returns neither `psi` nor any quantity derived from it [grid4_common.py:53–55](./bin/streams/grid4_common.py#L53) [spray.py:142–144](./src/ocen_dm/streams/spray.py#L142). Make it an opt-in calculation in `spray_unwrapped` so its existing default return remains intact.

4. **Parallelize independent models for throughput.** Processes can run separate model evaluations with fewer AGAMA threads each; this does not make one evaluation faster and does not change its mathematical inputs. **A for output, expected benefit only for throughput.** Benchmark process/thread combinations on the target Mac and guard against oversubscribing AGAMA/BLAS threads.

5. **Keep the current integration tolerance unless the PI accepts a numerical bound.** The packet reports that changing accuracy from `1e-8` to `1e-6` changed total log likelihood by 1.7, and `1e-5` changed it by −20 [packet:2017–2024](./.ask-codex-packet.XXXXXX.md#L2017). These are **B** changes, not bit-identical output. The measurements do not establish that either tolerance stays within a stated bound across models and seeds.

I would not replace the rotating host with an axisymmetric approximation: `host_potential` explicitly builds a rotating bar [restricted.py:60–89](./src/ocen_dm/streams/restricted.py#L60), so dropping it changes the model (**C**). The source shows a moving, fixed satellite potential is included in the particle orbit [spray.py:127–129](./src/ocen_dm/streams/spray.py#L127); it does not show that this force evaluation is a dominant cost. Profile before simplifying either potential.

**AGAMA units:** `agama_kpc()` calls `setUnits(mass=1, length=1, velocity=1)` every time [restricted.py:30–34](./src/ocen_dm/streams/restricted.py#L30). The spray path calls it again after constructing the host, including from `spray_unwrapped` and `rj_vj_R` [restricted.py:59](./src/ocen_dm/streams/restricted.py#L59) [spray.py:24](./src/ocen_dm/streams/spray.py#L24) [spray.py:109–119](./src/ocen_dm/streams/spray.py#L109). Those calls request identical units, so the warning alone does not prove a scaling error. But another module sets AGAMA length to 0.001 for pc units [backends.py:177](./src/ocen_dm/kinematics/backends.py#L177). Avoid mixing those paths in one process; verify units with a test that compares potential forces before and after repeated initialization and after importing/running the pc-unit backend.

### Assumptions and strongest argument against my recommendation

I assume independent particle integrations produce the same results regardless of which other particles are in the AGAMA orbit call. The test’s bitwise comparison supports that for its cases, but it does not cover spin or peri-centred release. The strongest argument against making cutoff pruning the top speedup is that it breaks the stated full-stream contract and narrows what downstream callers can inspect, even though it preserves the likelihood’s selected subset.
